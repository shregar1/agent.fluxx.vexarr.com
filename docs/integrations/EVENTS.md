# Events Reference

This document describes the event system in the Fluxx Agent Integrations Framework, including event types, severity levels, and common events generated by each integration.

## Event System Overview

Events represent significant occurrences in your infrastructure that may require attention. Unlike metrics (which are continuous measurements), events are discrete occurrences.

## Event Structure

```rust
pub struct Event {
    pub title: String,           // Event title
    pub description: String,     // Detailed description
    pub severity: EventSeverity, // Info, Warning, Error, Critical
    pub source: String,          // Integration name
    pub event_type: String,      // Event category
    pub timestamp: SystemTime,   // When it occurred
    pub metadata: HashMap<String, String>, // Additional context
}
```

## Severity Levels

| Level | Description | Action Required |
|-------|-------------|-----------------|
| **Info** | Informational | None |
| **Warning** | Potential issue | Monitor |
| **Error** | Problem detected | Investigate |
| **Critical** | Service impacted | Immediate action |

## Common Event Types

### Connection Events

| Event Type | Severity | Description |
|------------|----------|-------------|
| `*_unavailable` | Critical | Cannot connect to service |
| `*_access_failed` | Critical | Authentication failed |
| `connection_failed` | Error | Connection attempt failed |

### Performance Events

| Event Type | Severity | Description |
|------------|----------|-------------|
| `high_memory_usage` | Warning | Memory usage above threshold |
| `high_cpu_usage` | Warning | CPU usage above threshold |
| `high_disk_usage` | Warning | Disk usage above threshold |
| `slow_queries` | Warning | Query latency high |
| `high_connection_count` | Warning | Too many connections |

### Resource Events

| Event Type | Severity | Description |
|------------|----------|-------------|
| `queue_backlog` | Warning | Queue depth high |
| `high_consumer_lag` | Warning | Consumer lag high |
| `memory_alarm` | Critical | Memory limit reached |
| `evictions` | Warning | Cache evictions occurring |

## Handling Events

### Filtering by Severity

```rust
let critical_events: Vec<_> = events
    .iter()
    .filter(|e| e.severity == EventSeverity::Critical)
    .collect();
```

### Filtering by Source

```rust
let db_events: Vec<_> = events
    .iter()
    .filter(|e| e.source == "postgresql")
    .collect();
```

### Sending Alerts

```rust
for event in events {
    match event.severity {
        EventSeverity::Critical => pagerduty.send(&event).await,
        EventSeverity::Error => slack.send(&event).await,
        EventSeverity::Warning => log.warn(&event),
        EventSeverity::Info => log.info(&event),
    }
}
```

### Event Deduplication

```rust
use std::collections::HashSet;

let mut seen = HashSet::new();
let unique_events: Vec<_> = events
    .into_iter()
    .filter(|e| seen.insert(format!("{}:{}", e.source, e.event_type)))
    .collect();
```

## Event Correlation

Group related events:

```rust
// Find all connection failures
let connection_issues: Vec<_> = events
    .iter()
    .filter(|e| e.event_type.contains("connection") || e.event_type.contains("unavailable"))
    .collect();

// Check if database issues correlate with application errors
let db_issues = events.iter().any(|e| e.source == "postgresql" && e.severity == EventSeverity::Critical);
let app_errors = events.iter().any(|e| e.source == "application" && e.severity == EventSeverity::Error);

if db_issues && app_errors {
    println!("Application errors likely caused by database issues");
}
```

## Best Practices

1. **Set appropriate severity levels** - Don't make everything Critical
2. **Include context in metadata** - Helps with debugging
3. **Avoid alert fatigue** - Deduplicate and throttle events
4. **Correlate events** - Look for patterns across services
5. **Track event trends** - Are certain events increasing?
